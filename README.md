# BrickDraft · 像素积木 · 乐高微颗粒图

把一张图片变成乐高微颗粒画（1×1 颗粒马赛克）的桌面工具。导入照片 → 自动量化到乐高真实色卡 → 逐颗预览 → 统计零件清单 → 导出施工图。

技术栈：**Wails3（Go）+ Vite + Vue 3 + TypeScript**。图像量化、颗粒排版、导出渲染全部在 Go 侧完成，前端只负责画布绘制与交互。

## 功能

- **图源**：导入 png / jpeg / gif / bmp / webp，或从内置示例库挑一张照片 / 一个场景
- **示例库**：36 张实拍照片 + 1000 个程序化场景，点左侧「示例」打开画廊（Esc 关闭）。支持按名称 / 类别 / 关键词 / 编号搜索、按类别筛选、每页 48 个翻页，以及「随机」按钮。缩略图懒加载（可见项才渲染），翻页不卡顿。照片排在库首并带「实拍」角标，搜「实拍」可只看照片
- **比例自适应**：换图后高度自动按原图比例推导，方形场景得到正方形网格（64×64），4:3 场景得到 64×48
- **成品尺寸**：宽度 8–320 颗粒可调（预设 32 / 48 / 64 / 96 / 128），高度按原图比例自动推导；实时显示 1×1 颗粒的实际厘米尺寸
- **颗粒类型**：微粒粒（1×1 / 全部 1×1 板）、回圆粒、光面、薄板拼接（1×1–1×8）、标准砖（1×1–1×8）
- **调色板**：经典色卡（41 色）、人像 16 色、高饱和 16 色、灰度 8 色；用 CIEDE2000 色差匹配最近色
- **影调**：亮度 / 对比度 / 饱和度实时调整，可开关 Floyd–Steinberg 抖动
- **画布编辑**：画笔 / 吸管 / 平移，滚轮缩放，撤销重做，手动改单格颜色
- **零件清单**：按颜色统计用量条，按颜色 × 零件号汇总 BOM（数量、重量）
- **导出**：PNG 效果图、1:1 毫米施工图（SVG）、按色分步图（SVG）、零件清单（CSV，带 BOM）
- **工程文件**：`.xiangsu`（JSON，内含源图 dataURL，可单独重开）

## 示例库

示例库分两半：**36 张实拍照片**（编号 1001–1036，排在前面）和 **1000 个程序化场景**（编号 1–1000）。

### 为什么要有照片

程序化场景画得再好也只是插画。每一根胡须、每一扇窗都得写成一个条件判断，而 64 格上能表达的只有轮廓和色块——猫是一组「耳朵 + 胡须 + 尾巴」的符号，不是一只猫。这是方法本身的限制，不是修参数能解决的。

照片没有这个问题：它有真实的光、真实的材质、真实的层次。36 张照片覆盖了全部 9 个类别（每类 4 张），在 App 里走的是和用户自己导入的图片**完全相同**的量化管线，所以点开一张照片看到的颗粒图，就是这个软件处理真实照片的效果。

照片用 `go:embed` 内嵌，52px 见方缩到 512px、JPEG q88，36 张合计 2.1 MB。缩略图编码成 JPEG（同样的 256px，PNG 要 100 KB 一张，JPEG 只要 15 KB）。照片缩略图走双线性重采样，画布走原图直接降采样——量化器自己做面积平均，比按格采样更准。

### 程序化场景：玩具风

1000 个场景全部由代码生成。每个场景只是一个编号（1–1000），类别、配色、比例、名字都由编号派生，因此：

- **可搜索**：名字形如「落日 · 群山」「冬至小猫手记」，编号也可直接搜
- **分布均匀**：9 个类别 × 12 种配色，编号按 `n*13 / n*41 / n*83 / n*97 mod 1000` 四轴错开，任意筛选结果都有足够的多样性
- **任意尺寸都成立**：场景是 `func(x, y, w, h float64) [3]float64`，按格子中心采样并返回色卡原色，换 32 / 64 / 128 格都是同一张构图

第一版是「版画风」：连续渐变的地面、抖动纹理、雾气、轮廓光。看起来像一张印刷海报，而不像小朋友能拼的东西——这就是「太假」的第一层来源。

第二版改成平面色带之后仍然假，原因换了地方，是「颜色」和「边界」：

- 天空/地面还是用 `ramp()` 在色卡之间插值，三个色阶之间插出来的全是「洗衣粉蓝」「灰绿」，任何一盒乐高里都没有这种砖；同一张图里出现四五条这种条纹，看着就像色谱对照表。
- 配色从 mood 取，而 mood 是为氛围调的：「海洋」给的是沙蓝天 + 青绿地，于是花盆站在水面上，「日落」给的是紫色地面。氛围色适合水彩，不适合玩具。
- 主体没有边界。平涂色块直接接背景，缩略图上就是一个色斑。

所以 `toy` 分支现在有四条硬规则：

1. **只用色卡里的砖色，不插值**。天空 = `sky[0]` 上半 + `sky[1]` 下半，一条硬边；地面 = 两条砖色带（草地亮绿/绿、雪地白/浅蓝、沙地沙/深沙、柏油浅灰/深灰、水面水蓝/深青）。落到量化器上，每一格都正好是一块砖。
2. **玩具调色板整表重写**（`toyMoods`）。12 种 mood 各给一套 sky/earth：晴日蓝顶浅蓝、樱花粉顶白、日落橙顶亮黄、深夜深蓝顶黑、沙漠亮黄顶沙。地面不再由 mood 决定，而是由场景类型决定（`groundKind()`：草地/雪地/沙地/岩石/水面/柏油），花盆下面永远是地，不是水。
3. **一格深色描边**（`outlineWrap`）。整幅画先画满一格网格，再把主体边缘内侧一格压暗 66%。这是印刷拼图/乐高说明书的标准做法：它把主体从背景里「抠」出来，顺便吃掉斜边上的一格锯齿。
4. **主体放大 1.18 倍**（`sceneZoom`），以地平线为锚点缩放——脚不离地，被裁掉的是上方多余的天空。主体占满画面才有「颗粒图」的感觉，缩在中间三分之一就是一张海报。

细节上继续做减法：胡须、嘴缝、山体裂纹、墙面砖缝、蛋糕热气、行星虚线轮廓，在 64 格上都是「一个黑点」，删掉反而更像玩具。浅色场景里主体和背景的明度差不足时自动加深（`separate()`）。

主体改成了「两面色」的平面造型：山有受光面和背光面，塔楼有檐口和窗台，蛋糕有夹层和淋糖，星球是两种饱和砖色交替的条纹。单一平涂的三角形/矩形，是「贴纸感」的另一个来源。

| 类别 | 主体配方 | 示例 |
| --- | --- | --- |
| 自然 | 三座三角山（受光面 + 背光面 + 雪帽）、三棵松树、云和太阳 | 黎明 · 群山 |
| 动物 | 坐猫：圆头、宽耳、梨形身体、白肚兜与爪子、髋侧弧尾、圆眼高光 | 冬至小猫手记 |
| 城市 | 两排楼房（远排淡、近排深），大格窗带窗台、门、天线 | 林间城市小品 |
| 建筑 | 尖顶小屋（烟囱、门把手、黄窗）/ 带旗帜和雉堞的塔楼 / 条纹灯塔 | 海风灯塔 |
| 美食 | 三层生日蛋糕：棕色蛋糕体、白色/粉色淋面、滴落奶油、樱桃 | 午后蛋糕 |
| 交通 | 帆船（深船身 + 白甲板线 + 宽主帆 / 前帆 / 三角旗）或彩色小车（窗、车灯、轮毂） | 夏日小船与山 |

12 种配色情绪为晴日 / 日落 / 暮色 / 深夜 / 雪原 / 樱花 / 海洋 / 秋林 / 霓虹 / 沙漠 / 极地 / 苔原，每种给出 sky / earth / warm / lit 四组色卡。

**建筑、城市、食物、花朵、人物衣服、车船不再从 mood 取色**，改用固定砖色（沙色 / 浅灰 / 沙绿 / 淡蓝 / 红 / 珊瑚 / 棕），再按对比度微调。动物毛色从土色阶里按对地面的明度差挑（`coatColour()`）：从 mood 的强调色里取毛色，是「粉色的猫站在粉色的天上」的由来。

### 人物为什么不再是剪影

旧版用剪影 + 轮廓光，理由是 64 格画不出五官——鼻子一格、眼睛一格，相邻两格会糊成黑带。但在玩具风里这条不成立了：眼睛两格宽、嘴是一段 1 格厚的圆弧、头发是一整块碗盖，全部落在格子边界上，`separate()` 保证皮肤和背景有明度差。剪影在深色配色里会变成一个「带黄边的黑影人」，反而不像给小朋友看的图。

### 取景

场景统一画在单位正方形的「设计框」里，`frameFor(aspect)` 决定网格看到的是哪一块：

- 每格在横纵方向覆盖的设计单位相同 → 图形不变形
- 窗口的宽高比等于网格宽高比 → 横图是全景、竖图是中间的切片，而不是被拉扁的副本

缩略图首次请求时渲染，Go 侧带 420 项 LRU 缓存；前端只对当前页的卡片发请求。


## 开发与构建

需要 Go 1.24+、Node 20+、[wails3 CLI](https://v3.wails.io/)。

```bash
wails3 dev      # 开发模式（热重载）
wails3 build    # 产出 bin/xiangsu.exe（Windows）
go test ./...   # 跑单元测试
```

前端依赖安装建议走国内镜像：

```bash
cd frontend && npm install --registry=https://registry.npmmirror.com
```

## Windows / WebView2 说明

部分机器上的安全软件会拦截 WebView2 的渲染沙箱，表现为进程存在但窗口不显示；另有机器在 GPU 合成路径上一触发重绘，渲染进程就直接退出（窗口消失、进程结束）。程序默认追加 `--no-sandbox --disable-gpu` 规避这两类问题（本应用的画布只有几百个颗粒，软件渲染没有性能压力），并提供以下环境变量作为逃生通道：

| 变量 | 作用 |
| --- | --- |
| `XIANGSU_WEBVIEW_SANDBOX=1` | 恢复默认沙箱行为 |
| `XIANGSU_WEBVIEW_GPU=1` | 重新开启硬件加速 |
| `XIANGSU_WEBVIEW_ARGS=--disable-gpu,...` | 追加自定义 WebView2 启动参数 |
| `XIANGSU_WEBVIEW_PATH=...` | 指定 WebView2 运行时目录 |
| `XIANGSU_WEBVIEW_DATA=...` | 指定 WebView2 用户数据目录（默认在 %AppData%\xiangsu\webview） |
| `XIANGSU_DEBUG=1` | 打开 Wails 调试日志 |

> 同一份 WebView2 用户数据目录不要同时被多个实例使用；反复强杀进程后若出现异常，删掉 `%AppData%\xiangsu` 再启动即可恢复干净配置。
